## 1. Выбор ресурсов и параметров

### 1.1 Виртуальные машины (yandex_compute_instance)

```

| Параметр | Значение (dev) | Обоснование |
|---|---|---|
| `cores` | 2 | Достаточно для dev/test нагрузки Medical API и Fintech API |
| `memory` | 4 GB | Java-приложение (Spring Boot) требует ≥1.5 GB; 4 GB даёт комфортный буфер |
| `platform_id` | standard-v3 | Intel Ice Lake — актуальная платформа Yandex Cloud, лучшая цена/качество |
| `nat = false` | — | VM в приватной подсети; интернет через `yandex_vpc_gateway` (NAT Gateway) |

---

### 1.2 Диски (yandex_compute_disk)

| Параметр | Значение | Обоснование |
|---|---|---|
| `type = "network-ssd"` | network-ssd | SSD обеспечивает стабильный IOPS для приложений |
| `size = 15` | 15 GB | Достаточно для ОС + JVM + приложение |
| `image_id` | Ubuntu 22.04 LTS | Получаем через `data "yandex_compute_image"` — всегда актуальная версия |

**Зачем отдельный ресурс для диска** (а не `initialize_params` в VM):
- Диск может пережить удаление VM (данные сохраняются при пересоздании)
- Можно снять snapshot диска независимо от VM
- Явная ссылка `disk_id` делает зависимости прозрачными в Terraform-графе

### 1.3 NAT-настройки


| Подход | `nat = true` на VM | `yandex_vpc_gateway` |
|---|---|---|
| **Применение** | Одна VM | Целая подсеть (k8s-кластер, 10+ VM) |
| **IP-адреса** | Уникальный IP на каждую VM | Один общий IP для всей подсети |
| **Вайтлистинг у партнёров** | Сложно — IP меняется при пересоздании | Просто — один статичный IP |
| **Безопасность** | VM доступна из интернета по публичному IP | VM полностью приватная |
| **Стоимость** | Платный публичный IP на каждую VM | Один NAT Gateway на всю сеть |

Для domain-сервисов и k8s-нод приватность критична: Medical API не должен быть доступен напрямую из интернета — только через API Gateway.

### 1.4 Managed Kafka (yandex_mdb_kafka_cluster)

### 1.5 Managed ClickHouse (Corporate DWH)

ClickHouse — колоночная аналитическая БД:

| Параметр | Значение (dev) | Обоснование |
|---|---|---|
| `resource_preset_id` | s2.micro | Dev: достаточно для тестирования схем и пайплайнов |
| `disk_size` | 32 GB | Сжатие ClickHouse ~3–5×; 32 GB хранит ~100–160 GB несжатых данных |
| `disk_type_id` | network-ssd | SSD критичен для аналитических запросов с большим I/O |

**Почему ClickHouse вместо PostgreSQL для DWH:**
- Колоночное хранение: запросы `SELECT AVG(), GROUP BY` в 10–100× быстрее
- Сжатие данных: реальные объёмы аналитики занимают в 3–5× меньше места
- Горизонтальное шардирование: Managed ClickHouse масштабируется без downtime

## 2. Причины использования декларативного подхода (Terraform)

### 2.1 Декларативный vs Императивный подход

| Аспект | Скрипты (`yc` CLI) | Terraform (декларативный) |
|---|---|---|
| Описание | «Создай VM, потом диск, потом сеть» | «Целевое состояние: должны быть VM + диск + сеть» |
| Идемпотентность | Повторный запуск создаст дубликаты | `apply` → только нужные изменения |
| Зависимости | Ручной контроль порядка | Terraform строит граф зависимостей автоматически |
| Откат | Писать rollback-скрипты вручную | Предыдущая версия кода + `apply` |
| Drift detection | Нет | `terraform plan` показывает ручные изменения |

## 3. Как IaC обеспечивает воспроизводимость и масштабируемость

### 3.1 Воспроизводимость

| Сценарий | Без IaC (ручные скрипты) | С Terraform (IaC) |
|---|---|---|
| Новое dev-окружение | 2–3 дня ручной настройки | `terraform apply` → 30–60 минут |
| Восстановление после сбоя | Недели (настройка по памяти/документации) | `git clone` + `terraform apply` → 1 час |
| Аудит конфигурации | Ручная проверка каждого ресурса в консоли | `git diff` + `terraform plan` |
| Onboarding инженера | Читать wiki и документацию | Читать код = понять инфраструктуру |

### 3.2 Масштабируемость через переменные

Одна кодовая база позволяет держать три окружения через разные `.tfvars`:

### 3.3 Добавление нового партнёра = 5 строк кода

```hcl
# Подключить производителя МРТ-оборудования:
resource "yandex_mdb_kafka_topic" "mri_devices" {
  cluster_id = yandex_mdb_kafka_cluster.main.id
  name       = "partners-mri-v1"
  partitions = 2
}
```

`terraform apply` → новый топик создан. Остальные 34 ресурса не затронуты.
